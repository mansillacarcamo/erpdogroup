Sistema de Backup Automatico — DoGroup

Documento de instrucciones para administrar la copia de seguridad del sistema. Version 1.0

1. Que respalda el sistema

El backup guarda la informacion critica del sistema en un archivo .zip dentro de la carpeta backups/ del proyecto:

  • controlgastos.db — base principal (gastos, OC, cotizaciones, usuarios, obras, clientes, proveedores).
  • ocdogroup.db — base secundaria del modulo OC.
  • ocdogroup/ocdogroup.db — copia del subsistema.
  • uploads/ — todos los adjuntos: comprobantes de gastos, archivos asociados a OC, etc.
El backup mantiene los ultimos 12 archivos automaticamente. Si corre cada 5 dias, equivale a unos 60 dias de historial.

2. Archivos del sistema de backup

ArchivoFuncion
backup_auto.ps1Script PowerShell que crea el .zip. Lo ejecuta el Programador de Tareas cada 5 dias.
restaurar.ps1Script manual para restaurar un backup. Lo ejecutas vos cuando hace falta.
backups/backup.logHistorial de cuando corrio el backup, exito o error.
backups/backup_*.zipCada archivo .zip es una copia completa con fecha y hora.

3. Activar el backup automatico (una sola vez)

  1. Abrir PowerShell como Administrador:
    • Tecla Windows -> escribir "powershell" -> click derecho -> "Ejecutar como administrador".
  2. Pegar y ejecutar este comando (todo en una sola linea):
schtasks /Create /TN "DoGroup_Backup" /SC DAILY /MO 5 /ST 02:00 /RL HIGHEST /F /TR "powershell.exe -NoProfile -ExecutionPolicy Bypass -File `"C:\Users\INGENIERIA SISTEMAS\Desktop\dogroupsistema\backup_auto.ps1`""

Listo. La tarea queda registrada en el Programador de Tareas de Windows y se ejecuta sola cada 5 dias a las 02:00 AM.

Si la PC esta apagada a las 02:00, Windows ejecuta el backup la proxima vez que la enciendas.

4. Comandos utiles para administrar la tarea

Que necesitasComando
Ver si la tarea existe y cuando correra schtasks /Query /TN "DoGroup_Backup" /V /FO LIST
Ejecutar el backup ahora mismo (prueba) schtasks /Run /TN "DoGroup_Backup"
Eliminar la tarea programada schtasks /Delete /TN "DoGroup_Backup" /F
Cambiar la frecuencia (ej. cada 7 dias) Volver a ejecutar el comando del paso 3 cambiando /MO 5 por /MO 7.

5. Restaurar un backup

IMPORTANTE: antes de restaurar, detener el servidor (Laragon -> "Stop All"). Si Apache esta sirviendo el sistema mientras se sobrescribe la base de datos, la base se puede corromper.
  1. Abrir PowerShell (no necesita ser administrador).
  2. Ejecutar:
powershell -ExecutionPolicy Bypass -File "C:\Users\INGENIERIA SISTEMAS\Desktop\dogroupsistema\restaurar.ps1"

El script:

  1. Muestra una lista numerada con todos los backups disponibles, ordenados del mas reciente al mas antiguo (con fecha, hora y tamano).
  2. Te pide elegir cual restaurar. Si presionas Enter sin numero, restaura el mas reciente.
  3. Te pide escribir SI en mayusculas para confirmar.
  4. Antes de sobrescribir, guarda los archivos actuales en backups/_pre_restore_<fecha>/ por si querias revertir.
  5. Descomprime el .zip elegido y restaura las bases .db y la carpeta uploads/.

Cuando termina, volver a iniciar el servidor (Laragon -> "Start All").

6. Que NO hacer

  • No borrar manualmente archivos .zip de backups/ a menos que la carpeta este saturada y no quepan mas. El script ya elimina solo los antiguos cuando supera 12.
  • No editar archivos .db con un editor de texto. Son binarios, se corrompen.
  • No apagar la PC justo a las 02:00 si tenes corriendo el backup; esperar a que termine (suele tardar pocos segundos).
  • No mover los archivos backup_auto.ps1 ni restaurar.ps1 de la raiz del proyecto: la tarea programada apunta a esa ruta.

7. Recomendacion de respaldo externo

Una vez al mes, copiar el .zip mas reciente de backups/ a un pendrive o disco externo. El backup local protege contra borrados accidentales y errores de software, pero no protege contra robo, incendio o falla del disco duro. Una copia externa cierra ese riesgo.

8. Verificacion periodica

Cada cierto tiempo (recomendado: una vez al mes) abrir backups/backup.log con el Bloc de Notas y verificar:

  • Que las ultimas lineas sean Backup OK y no ERROR.
  • Que la fecha del ultimo backup sea reciente.
  • Que la cantidad de .zip en backups/ no este creciendo sin control (deberian quedarse en 12).

9. Notificacion por correo

Despues de cada backup automatico, el sistema envia un correo a:

deptoinformatica@dogroup.cl

El correo incluye:

  • Estado: OK (verde) o ERROR (rojo).
  • Fecha y hora en que corrio el backup.
  • Nombre del archivo .zip generado.
  • Tamano del archivo en MB.
  • Si hubo error, el mensaje del error.
Para que el correo funcione, el archivo smtp_config.php debe estar configurado con un servidor SMTP real (host, usuario y contrasena). Si el archivo todavia tiene los valores por defecto, completar antes de activar el backup automatico.

Componentes involucrados:

ArchivoFuncion
smtp_config.phpServidor SMTP, usuario, contrasena.
backup_email.phpScript PHP que arma y envia el correo via PHPMailer.
backup_auto.ps1Llama al script PHP al final de cada backup, pasandole el estado.

Si el correo no llega, revisar:

  • Que backup.log diga "Notificacion enviada" en la ultima ejecucion.
  • Que php.exe este disponible en el PATH o en C:\laragon\bin\php\.
  • Que la carpeta de spam del correo destino no haya filtrado el mensaje.
  • Que las credenciales de smtp_config.php sean validas.
